# A 推进 — 实验规则（11-10 到 11-24）

- 分组：`assignment.json`（指纹 `assignment.sha256`，生成后不改）。22 个单位，「推」组每天在首页顶部轮出 1–3 件，「对照」组两周里什么都不加。
- 新冒出来的事：按 `new_unit_rule`（盐 + 编号的 SHA-256 首字节为偶数 → 推）自动分组。
- 结果怎么数：`a_analyze.py`（指纹 `a_analyze.sha256`，事先定好）。Horizon 看 `status=done` 和 `completed_at`；首页看「做完了」且没被撤回。
- 过线：推组完成率 ≥ 对照组 2 倍，且差值 95% 置信区间不含 0（Newcombe）；同时报费舍尔精确检验。

## 建议区的边界（防止污染对照组）

- 11-24 之前，「建议」（换掉含糊的步骤、挪进冷藏、合并重复）**只能针对推组单位或不在实验里的事**；对照组单位一条建议都不出。
- 理由：对对照组提建议、挪动或合并，本身就是一种干预，两组就不可比了。
- 落实：生成建议的程序写入 `push/suggestions.jsonl` 前按 `assignment.json` 过滤，并有测试覆盖；11-24 的分析前再用脚本核对一遍：窗口内每条「同意」记录对应的单位都不在对照组。

**11-09 定**：建议区整体推到 11-24 实验结束后再开（见 `home/star/FINISH-CHECKLIST.md` 第 2 条）。实验期间首页只有「今天先做这一步」这一种干预。

**11-10 02:26 补**：台式机 Windows 时区是美东（UTC-5），首页原来按本机日期判断实验窗口，所以 11-10 北京时间 0:00–2:26 台式机首页没有推进卡片（笔记本正常）。已改成两台都按北京日期选推送（`server.py` 的 `read_push`），笔记本结果逐字不变，台式机现在和笔记本同一天推同样三件。分析口径本来就是北京日期，不受影响。星图里推组的事聚焦时也显示同一条「第一步」（只给推组，窗口外不显示）。
