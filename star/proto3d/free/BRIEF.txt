任务：做「星图」的 3D 版（A 版：你全权负责所有的动向和布局）

你是一位资深的交互与视觉工程师。请做出你认为最好的 3D 版星图，一个单文件网页：HTML + 内联 CSS + 内联 JavaScript。要求：

【交付方式：分部件写（重要，请严格照做）】
网络对一次很长的回复不稳定：一次回复里写得太长会被掐断，整个回复作废、要从头再来（已经发生过）。所以不要一次写完整个页面，而是分成下面这些部件，每个部件各用一次写文件调用，每个部件不超过 300 行（宁可多分几个）。部件都写进当前目录的 parts/ 文件夹（已存在）：
  parts/00-head.html   从 <!DOCTYPE html> 写到静态 DOM：<head>（meta、<title>、<style> 里的全部样式）和 <body> 里的静态元素（画布或容器、#top-right、输入框 #idea-input、图例、操作提示等）；最后一行是一个单独的 <script> 开标签。
  parts/20-core.js     PRESETS、状态、节点和线的建立（从 DATA 来）、布局（力）、镜头与投影或 3D 变换。
  parts/30-render.js   绘制：背景、线、球、图标、文字与摆放、涟漪、皮筋。
  parts/40-input.js    指针和键盘：转镜头、拖球、皮筋、切线、聚焦、输入框打字。
  parts/50-boot.js     启动：创建面板、/api/health 检查、动画循环、window.__star3d 测试钩子。
  parts/99-tail.html   只有一行：</script></body></html>
某个部件放不下 300 行时，拆成 21-xxx.js、31-xxx.js 这样的续篇（文件名里的编号决定拼接顺序，00 最前，99 最后）。
我用脚本把它们拼成一个页面：先是 00-head.html，接着 DATA、声音模块、布局力面板这三份现成代码的全文（我来内联），然后是 parts/ 里所有 .js 按编号顺序，最后是 99-tail.html。所以：所有 .js 部件共享同一个全局作用域，后面的部件可以直接用前面部件里的函数和变量；.js 部件里不要写 <script> 标签；一个函数不要被拆在两个部件之间；不要重复声明 API.txt 里列出的已占用名字。
全部部件写完后：通读一遍你写的各部件，检查括号配对、被引用的函数和变量都已定义（部件之间的名字要对得上），有错用替换工具改；然后在当前目录写 DONE.txt（一行：完成）。最终回答 100 字以内，只说做了什么、有哪些你自己拿不准的地方。

【星图是什么】
一个记想法、看清想法之间联系的工具。每个概念是一个球：球里有线条图标，球下面是文字。大球是「星座中心」（粗体名字），围着它的小球是它的成员；颜色代表领域；白色的球是还没归类的想法；虚线圈是 AI 提议的「可能性」（点一下就留下）；虚线加一句问句，是 AI 提议的「关系」。2D 版已经做好，手感被用户反复调过；现在要你做它的 3D 版。数据、图标、声音、布局力面板都已备好，由我在拼页面时原样内联在你的代码之前，你的代码里可以直接用（接口见 API.txt）：DATA（4 个星座和成员、想法、19 个图标的 SVG path、领域和颜色、线索、可能性示例等；其中 at 是 2D 坐标，3D 不用）、声音模块（用 Web Audio 现场合成，不用音频文件）、布局力面板 createForcesPanel。

【你可以完全自己决定】
布局算法、镜头模型、深度的含义、动效、视觉语言、颜色的处理、球和文字的呈现方式，都由你决定。目标：让人想一直玩下去、又不吵。

【用户定下的手感原则（必须保留）】
1. 画面安静。留白是主体。没有用户操作时，什么都不动（不要自动旋转、不要持续漂移）。文字不加底框、不加气泡；可以给文字描一圈深色细边，让线穿过文字时依然读得清。
2. 声音只有 audio.js 里那五种，而且只在「拉」和「切」的时候出现（拉皮筋的吱、松手的嘣、弹出火花的嗖、一划切线时的嗖和咔）。悬停、点击、落地、长出可能性，一律没有声音，也不要有持续循环的声音。第一次点击或按键时调用 ensureAudio()。
3. 橡皮筋：按住任意一条线的中间往外拉，线变成两股皮筋（V 形）；起步和鼠标 1:1，越拉越有阻力；松手弹回，过冲摆动 2 到 3 下才停；线永远拉不断。拉到张力 0.7 以上松手，会弹出一颗火花，火花停下的地方开出一个虚线圈「两者之间」。在屏幕空间里做，参数：屏幕像素里 stretchMax 125，位移 s = 125 * tanh(d / 125)，张力 t = s / 125；皮筋点跟手的弹簧 ω26、ζ0.5；松手回弹弹簧 ω20、ζ0.2；抓住时线宽 2.2 像素，随拉伸变细到 0.45 倍；颜色随张力从线本色变暖。拉的时候调用 creak(t, 1)，松手调用 twang(t, 张力>=0.7)。
4. 切线：在空白处按住快速一划，划过的线被切断。判定：按下后 300 毫秒内，某一小段移动划过了某条线、并且速度不低于 700 像素/秒，就算一划（慢慢拖动则是转动镜头，不切线）。一划切断的所有线，Ctrl+Z 一次全部接回。声音：开始一划时 swishSound()，每切断一条 sliceSound()。
5. 单击一个球聚焦：它和它相连的（两跳以内）保持亮，其余压暗到 16%，文字也跟着变暗；点空白处退出聚焦。聚焦不要让画面晕：不要突然缩放，镜头只轻轻转向或挪动，用慢而柔的弹簧。
6. 鼠标悬停不要出现任何涟漪、白圈、闪光；只有刻意点击时才出一圈涟漪（约 1.45 秒）。悬停时球自己稍微变亮可以。
7. 底部居中的输入框（宽 560 像素、高 46、圆角、半透明深色，id 必须是 idea-input，占位文字：想到什么，直接打，回车记下）：打字回车记下一条新想法，它落进场景（落在文字最相近的球旁边，没有相近的就落在前方的空白处），然后长出 3 条示例可能性（用 DATA.placeholder）。页面一打开输入框就聚焦。
8. 球里有图标（DATA.icons）；颜色按领域（星座的 domain 对应 DATA.domains 的 color）；状态用亮度：running 1.3、explore 1.0、pool 0.85、frozen 0.55。想法用 DATA.unsortedColor。
9. 左下角图例（领域色点 + 名字）；左上角一行操作提示（8 秒后淡出）；右上角写版本名「3D · Gemini 自由版」。
10. 文字永远不重叠：显示不下的文字就不显示，按优先级留（被聚焦的 > 星座名 > 想法 > 成员）。

【布局力面板（Obsidian 图谱「Forces」那一套）】
四个 0 到 1 的旋钮：向心力（把所有节点、尤其是星座中心往场景中心拉）、排斥力（节点之间互相推开）、连线吸引力（相连节点互相拉近）、连线长度（相连节点之间的静止距离）。你的布局必须由这四个力驱动，改动后图要平滑重排。
- 用现成的 createForcesPanel（我会原样内联在你的代码之前，不要抄写或改它；接口见 API.txt）。
- 在 parts/20-core.js 的开头定义 const PRESETS = { claude: { center: 0.45, repel: 0.40, link: 0.50, distance: 0.40 }, gemini: { 四个数由你自己定，填你认为这个版本最好看的一组 } };。claude 那组先照抄占位值，我之后会自己调；gemini 那组是你的。创建面板时 initialMode 用 'gemini'，initial 用 PRESETS.gemini。
- 面板的 getStats 返回 { nodes, links, ideas, labelOverlaps, fits（整体是否都在窗口里）, nearestMin（最近两个节点的屏幕距离）, constellations: [{ id, title, members, ideas, status }] }。
- 页面通过 http 打开时（location.protocol 是 http: 或 https:），请求 /api/health，返回 ok 且 model 为真就调用 panel.setModelReady(true)；直接用 file 打开则不可用（保持默认 false）。
- applyAnchors(list)：DeepSeek 会给每个星座中心一个目标位置 { id, x, y, z }，x、y、z 都在 -1 到 1，-1 是窗口左 / 上 / 近，1 是右 / 下 / 远。请把它们换算成你的世界坐标里的目标，用 3 秒的临时牵引把星座拉过去，之后由四个力接管。
