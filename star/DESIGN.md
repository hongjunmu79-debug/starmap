## 2. 需求重新拆

最初的困扰：跟 AI 聊着聊着冒出好想法，想顺着往下走，但会话一发散就断线。拆开是五个环节：

| 环节 | 你要的 | WorkBuddy 版 | 新方案 |
|---|---|---|---|
| 收 | 手机随时录；网页、Claude、Agent 里看到就收；打开就能打字 | 只有页面里一个输入框 | 手机发 Hermes（已有）；电脑任何窗口热键；Claude Code 里一句话；首页和星图的输入框 |
| 存 | 自动保存、不丢、两台都有 | 一个浏览器的 localStorage | 首页的事件文件，Syncthing 双机同步（已有） |
| 找回 | 按时间、能搜、能接着改、记得从哪来 | 时间流和搜索有；来源只记个名字 | 时间视图保留；每条带来源（哪个窗口、哪段对话、当时在聊什么） |
| 看出联系 | 关系和可能性自己浮出来，你点头才算 | 灰线 = 离得近；提议 = 按文字哈希从 5 句里挑 | 按 19 件事成星座，想法自己落到相关的那片；Hermes 提问句式的关系；你点头才成立 |
| 顺着往下走 | 断了的线能接上；给我推荐，我挑认可的留下再往下长 | 没有 | 「长出可能性」：每条想法自动长出几条虚线方向，你挑着留，留下的还能接着长（5.10）；「带回对话」：把这条和连着的几条拼成提示词，贴回 Claude 接着聊 |

**这个工具的价值跟里面的想法数量成正比。** 5 个节点的画布是玩具；攒了三周、两百条之后，「周二那段对话里的想法其实接着周六那个」才会出现。所以「收」的摩擦是命脉；「联系」必须在量大时自己长出来，靠位置远近长不出来，得靠理解文字。

## 3. WorkBuddy 版的问题（都出自它自己的文档）

1. **做成了第五套系统。** 星图有自己的输入框和 localStorage：首页「记一笔」、手机发给 Hermes 的想法进不来，星图里记的也到不了首页。两个想法池，本身就是「断线」。
2. **第一优先级基本没做。** 「手机随时录」「在 Claude 里随手收」只落成了 `?from=xxx` 记个来源名；文件在台式机本地，手机打不开；数据只在一个浏览器里，清掉网站数据就没了。
3. **「看清联系」是假的。** 灰线只说明两个节点离得近，而远近取决于你把它放在哪；紫色提议是 `suggestLabel()` 按文字哈希从 5 句问句里挑一句。16 版把线的手感调得很好，线本身不带信息。
4. **摆放要你自己来。** 每条想法都得在画布上有个位置。记到一百条，要么堆成一团，要么你去整理，这正是你说的「先组织好结构」的负担。
5. **开场和「打开即输入」方向相反。** 每次打开先播 2.35 秒开场才交还交互，默认还停在画布。打开那一刻最该做的是让你打字，动画应该留给「有新东西」的时候。
6. **数据会自相矛盾。** 「否掉且不再出现」的 `dismissed`、拉断的 `blocked` 都不存，刷新就回来；没有删除记录，以后没法同步。
7. **只在 5 个节点上验过。** 自检是 `nodes=5`、760×380，最终画面没人亲眼看过。

## 4. 架构：一个来源，多个入口，两个视图

```
入口（只管写下，不分类）
  手机 → 飞书 / Telegram → Hermes
  任何窗口 Ctrl+Alt+J
  Claude Code 里说「记个想法」
  首页「记一笔」 / 星图输入框
        │ 都写成 idea 事件
        ▼
存储（已有，Syncthing 双机同步）
  home/content.json            19 件事 + 合并进来的原始想法
  home/events-*.jsonl          想法、进度（首页和星图都读）
  home/events-star-<主机名>     星图自己那一层：连线、否掉、位置
        │
        ├──▶ 首页 /       今天、想法池（不变）
        └──▶ 星图 /star   星空、时间

Hermes 每天 10:30：读 /api/star → 写「分拣」和「关系提议」到 events-hermes.jsonl
```

- **不新建**服务、端口、计划任务、数据库、云服务。星图是首页服务多出来的一个页面和两个接口；数据就是首页那几个文件。
- **手机只负责录。** 你最初的要求就是「手机快速录入，桌面查看和整理」。手机走 Hermes，不做手机版星图，所以也不需要 HTTPS、账号、云同步：WorkBuddy 待办里的「多端同步 / 上线」整条省掉。
- **AI 不进浏览器。** 可能性由 Hermes（手机来的）或首页服务（电脑上来的）生成，关系提议由 Hermes 每天做一次；浏览器里没有任何 API key。
- **以后真要做成给别人用的产品**：星图前端只认 `GET /api/star` 和 `POST /api/star-event` 两个接口，换一个云端实现同样的接口就行，前端不用重写。

### 4.2 手机端现在有两条路（2026-11-09 手机测试后记下）

同一个 Hermes（`director` 档案）里有两个技能会收想法，按你怎么说分流，最后都落进首页想法池：

| 你发的 | 哪个技能 | 路径 | 回复 | 多久能在首页看到 |
|---|---|---|---|---|
| 「记个想法：xxx」（开头就是这几个字） | `idea-capture`（11-06 建的老技能） | 直接追加 `idea` 到 `events-hermes.jsonl` | 「记下了，在首页想法池里」 | 1 分钟内 |

## 5. 星图页面

### 5.0 你当时给的动效参考，逐条对照（这一节是重点）

WorkBuddy 的问题不在参数没调好，在于用错了地方：你给的参考都是每天每一下都会碰到的交互，它把其中几条拿去做了每次打开播一遍的开场动画（A–E 五个方向），剩下的要么调到看不出来，要么跟着容器一起删掉了。

| 你当时说的 | WorkBuddy 做成了 | 原型里改成 |
|---|---|---|
| ① 生成导图：从一个模块向上下左右散开，弹簧，布局补间借鉴 FLIP | 开场动画的「爆开」；FLIP 挪去切换视图 | 「长出可能性」本身：虚线可能性从想法向四周弹出、带过冲，挡路的节点用 FLIP 式补间平滑让开；留下的那条再长就往外延伸，像思维导图 |
| ② 拖拽抛掷 + 画布边界感 | 只有拖空白平移的惯性，节点不能扔 | 节点能甩：带惯性滑行、撞屏幕边缘回弹，光晕被压扁再抖回来；画布平移的惯性和软边界也保留 |
| ③ 多人光标 + 立场驻留：鼠标进场、点击时 | 开场里一个虚构的「AI 光标」 | 你自己的鼠标有「场」：靠近时节点微微偏向你、变亮；停 0.4 秒放出涟漪，相连的节点依次亮、线上有光脉冲跑过去；点空白有小涟漪 |
| ④ magnetic 磁吸 | 系数 0.035，只在拖动时，几乎看不出来 | 拖着靠近另一个，明显被吸过去，70 以内「咔」地吸住、有黏性，松手就连上 |
| ⑥ 像泡泡、果冻，离近了有线连上，远了断掉 | 容器在 v13 删掉后，果冻感也没了 | 果冻感放在光晕上：随速度拉长、撞墙压扁、停下抖两下，文字不变形；拖星座中心，它的包含像果冻一样跟着；拉远超过 380 断开、两截回缩 |

| ⑤ 背景移动：无所谓 | 明确不做 | 不做，星点只呼吸 |

### 5.1 原样保留（WorkBuddy 已经定了的原则）

- 文字就是节点，无边界的淡光晕；深色星空，星点极少；文字 15px 高对比带暗影
- 同一对节点永远只画一条线；提议是虚线加问句，点它成立、× 否掉；同屏最多 3 个提议标签
- 静止时永远不会因为离得近就自动连线：线要么是你点头的提议，要么是你亲手拖过去吸上的
- 拉线不直接生成结构：拉满弹出的只是一条虚线可能性，你点了才算
- 时间 ↔ 星空的 FLIP 切换

手感参数（弹簧、惯性、阈值）和声音不再用 WorkBuddy 的数，以原型 `CFG` 为准。

### 5.3 布局

- 世界坐标固定 2400×1600；打开时镜头缩放到正好装下全部
- 6 个分组按扇区排：「在跑」4 件在中间一圈；学习、系统、创作、想法池围一圈；「冻结」放最外并调暗
- 事项是星座中心；它的「包含」绕它一圈（半径 70–110）
- 想法的落点：有确认连线 → 靠近对方；有 Hermes 写的归属 → 靠近那件事，画虚线提议；都没有 → 输入框上方的「新落下」带，按时间排
- 力导布局离屏一次算完（约 300 步）再显示；碰撞半径按文字宽度算，不叠字（顺带解决 WorkBuddy 待办 4 的穿模）
- **同样的数据永远得到同样的位置**（固定随机种子）。空间记忆全靠这个：「土地租赁在右上角」
- 拖过的节点写 `pin`，之后布局把它当固定点

### 5.4 远近分层

- 远景（缩放 < 0.9）：只写 19 个星座短名（标题里「：」或「（」前面那段，最多 10 个字）；其余是光点；没看过的新想法微微呼吸
- 中景（0.9–1.6）：再加上悬停的、新的、搜索命中的那几句
- 近景（≥ 1.6，或点了一颗星）：这颗星一跳、两跳以内的句子全部显示，其余压暗到 25%
- 字号始终是屏幕上的 15px，不随缩放变小

### 5.5 「新想法落进星空」：唯一要调到舒服的动效

- t=0：输入框已聚焦，星图直接显示最终布局，没有整体开场
- 有没看过的想法（时间晚于这台电脑上次打开），就逐条落入：从来处出现（在星图里打的从输入框升起；手机、热键、Claude Code 来的从顶边落下，带一个小来源字「手机 / 热键 / Claude」）→ 收拢 0.3s → 停 0.28s → 弹簧飞到落点，带过冲 → 落地涟漪 0.5s → 有提议的话 0.2s 后画出虚线

## 6. 数据契约

### 6.1 节点 id

- 事项：`item:<content.json 的 id>`
- 包含：`inc:<事项 id>:<原文去首尾空白后 sha1 的前 8 位>`
- 想法：`idea:<idea_id>`
- 一对节点的键：两个 id 排序后用 `|` 连起来

### 6.2 文件和写入方

每个文件只有一个写入方，这是 Syncthing 不冲突的前提。

| 文件 | 写入方 | 状态 |
|---|---|---|
| `events-<主机名>.jsonl` | 首页服务 | 已有 |
| `events-hermes.jsonl` | Hermes | 已有 |
| `events-mosaico.jsonl` | Mosaico | 已有 |
| `events-capture-<主机名>.jsonl` | 这台电脑上的热键和 Claude Code（每条一次写完整一行） | 已做（第 1 期） |
| `events-horizon.jsonl` | 桥 `home/horizon-bridge/horizon_bridge.py`（台式机 WSL，每 5 分钟，只读 Horizon 数据库） | 已做（第 1 期），台式机已装（2026-11-09） |
| `horizon-today.json` | 同一个桥（今天 / 逾期 / P0 待办快照，目前没人读；不是事件文件，首页不会当事件读） | 已做（第 1 期），台式机已装（2026-11-09） |
| `events-star-<主机名>.jsonl` | 星图接口（11/10 前由 preview.py 写） | 新增，第 2 期 |

`<主机名>` 和 server.py 的 `HOST` 一样：`socket.gethostname()` 里字母、数字、`_`、`-` 以外的字符换成 `_`。

首页服务读所有 `events-*.jsonl`，但只认 `done / undo / skip / idea / idea_edit / idea_drop / idea_note / promote` 八种（server.py 的 `EVENT_TYPES`）。所以星图的新类型首页看不到、不受影响；`idea` 和 `idea_drop` 首页照常认。

### 6.3 事件类型

所有事件都另带 `id`（32 位十六进制）、`ts`（UTC）、`host`。

| type | 谁写 | 字段 | 首页 |
|---|---|---|---|
| idea | 所有入口 | idea_id（= id）, text, via?, source?{app, title, cwd, context}, parent? | 进想法池（照旧） |
| idea_note | Hermes / 用户 | idea_id, belongs, first_step | 照旧 |
| idea_drop | 首页 / Claude / Hermes / 星图 | idea_id, reason?（deleted / merged / star）, into?, as? | 从想法池拿掉（照旧） |
| link | 星图 | a, b, kind, label? | 看不到 |
| unlink | 星图 | a, b | 看不到 |
| suggest | Hermes | a, b, kind, label, why | 看不到 |
| dismiss | 星图 | a, b | 看不到 |
| pin | 星图 | node, x, y（世界坐标） | 看不到 |
| edit | 星图 | node, text | 看不到（首页仍显示原文） |
| collapse | 星图 | node, on | 看不到 |
| suggest_node | Hermes / 首页服务 | parent, text, lens（可以变成 / 第一步 / 卡在 / 像 / 连着 / 两者之间）, to?（「连着」指向的节点）, parents?（两者之间：两个父节点） | 看不到 |
| dismiss_node | 星图 | node（那条 suggest_node 的 id） | 看不到 |

「留下」一条可能性 = 星图写一条 `idea`（`via: "star"`、`parent`、`lens`）加一条 `link`（kind `extends`）；它从此就是一条普通想法，也会进首页想法池，第 4 期由 Hermes 分拣。

`via` 取值：`hotkey` / `claude-code` / `horizon`（手机上的微信 / 飞书消息，经 Horizon 收件箱和桥）/ `feishu` / `telegram` / `star` / `home`；没有 via 的老事件当 `home`。

### 6.4 合成规则（`starapi.build_graph`）

- 读 content.json 和全部 `events-*.jsonl`（所有类型），按 id 去重（Syncthing 冲突副本会重复），按 ts 排序回放
- 想法的状态：最后一条 `idea` 之后没有 drop → 在池里（pool）；`idea_drop` 带 `reason: "star"` → 只在星图（star）；带 `reason: "merged"`，或没写 reason 但某条「包含」的原文和它一字不差 → 合并了：把 `idea:x` 当成那条 `inc:` 的别名，连线跟过去；其余 drop → 删了，不显示
- 「这是要做的事」= 用同一个 idea_id 再追加一条 `idea`，首页会把它放回想法池
- 一对节点只留一条线，优先级：确认 > 提议 > 结构（属于）；`unlink` 或 `dismiss` 过的一对，Hermes 的提议永远不显示
- 指向不存在节点的线：丢掉，记一行日志，不报错

### 6.5 接口

`GET /api/star`：

```json
{
  "version": 1,
  "groups": [{"id": "running", "name": "在跑"}],
  "nodes": [{"id": "idea:ad0c…", "kind": "idea", "text": "做一个桌游", "short": "做一个桌游",
             "group": "pool", "item": null, "ts": "2026-11-06T15:01:23+00:00", "via": "home",
             "source": null, "state": "pool", "belongs": "offline-social", "parent": null,
             "pin": null, "collapsed": false}],
  "links": [{"a": "idea:ad0c…", "b": "item:offline-social", "kind": "part_of", "state": "suggested",
             "by": "hermes", "label": "属于这件事吗？", "why": ""}],
  "dismissed": ["idea:…|inc:…"],
  "last_ts": "2026-11-07T11:00:00+00:00"
}
```

`POST /api/star-event`：body 是 6.3 里星图写的那几种（含 idea、idea_drop）。服务端补 id / ts / host，校验类型和长度（text ≤ 2000 字），追加到 `events-star-<主机名>.jsonl`。和首页一样只监听 127.0.0.1，校验 Host 和 Origin。
